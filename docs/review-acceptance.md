# 完整审核流程验收清单

## 自动化门禁

在 `app` 目录运行：

```bash
npm test
npm run build
cd src-tauri
cargo test
cargo clippy -- -D warnings
```

期望全部通过。`cargo test` 中的模型客户端测试会启动本地 loopback HTTP 服务；若沙盒禁止监听 `127.0.0.1`，需在允许本地 loopback 的开发环境中运行。

## 手工验收

| 场景 | 操作 | 期望结果 |
| --- | --- | --- |
| 模型测试绿灯 | 在 API 设置中选择 DeepSeek 或通用大模型配置，填写可用 API Key，点击“测试连接” | 显示“连接成功”，首页显示绿点和“模型已配置” |
| 模型测试红灯 | 使用错误 Key、不可达地址或极短超时点击“测试连接” | 显示稳定错误码；首页显示红点和“模型未就绪” |
| 可提取文件成功 | 添加 1 份可提取文本招标文件和 1 至 4 份可提取文本投标文件，点击“开始预检” | 显示“准备完成”和每个文件文本块数；按钮变为“开始审核” |
| 无文本文件局部失败 | 添加至少 1 份可读投标文件，同时添加 1 份扫描件或无可提取文本文件 | 可读文件保留；失败文件显示到对应行；任务可进入带问题状态 |
| 模型超时 | 使用会超时的模型服务或将测试服务延迟超过超时时间 | 返回 `modelConnectionTimeout` 或等价超时错误，不记录明文 Key |
| 四份投标查重 | 添加 4 份投标文件并完成审核 | 报告中出现 6 个两两查重组合 |
| 技术暗标 DOCX | 为投标文件关联 DOCX 技术暗标，包含页眉、页脚、页码或浮动对象等可疑项 | 报告中列出技术暗标辅助检查发现，标明需人工复核 |
| Markdown 汇总 | 审核完成后查看界面“结果预览”，并点击“打开结果目录” | 结果目录存在 `审核汇总.md`；界面可预览 Markdown；结果包含摘要、招标要求、逐份发现、查重、暗标发现、失败项、人工复核说明和“保定移动政企部 zhaoyun_bd@he” |
| Windows 便携 EXE/安装器 | 在 Windows 10/11 x64 执行 `npm run tauri build -- --bundles nsis` 并安装运行 | 程序可启动；WebView2 正常加载；配置、预检、审核和打开结果目录可运行 |

## 记录要求

Windows 验收需记录系统版本、构建命令、安装器路径、安装器大小、模型服务商、测试文件数量、是否生成 Markdown 汇总，以及任何失败错误码。
